## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.

## Restaurant partner accounts

Partners create an account from the frontend sign-in page with their restaurant name, contact name, email address, and password. New registrations create a restaurant in `pending` status. A global administrator must approve the restaurant before its partner can sign in; existing restaurants keep their current status.

The dashboard API uses bearer access tokens. Restaurant data endpoints require authentication and are scoped to the restaurant linked to the signed-in partner. Pending, rejected, and suspended partners cannot sign in or use existing access tokens. QR menu browsing, order placement, and order-status lookup remain public for restaurant customers.

The global administrator dashboard uses `/api/admin/dashboard` for database-backed platform and order metrics, and `/api/admin/restaurants` for searchable, paginated partner management. These endpoints require an authenticated global administrator and are kept separate from restaurant partner endpoints. Partner status changes are recorded in `audit_logs`.

The global administrator can start a read-only partner dashboard view through `/api/admin/restaurants/{restaurant}/view`. Subsequent authenticated API requests must include `X-Admin-View-Restaurant` with the selected restaurant ID. The API scopes all existing restaurant resources to that restaurant, allows suspended restaurants to be inspected, and rejects all write methods in this mode (including public QR order submission). The administrator's original token and identity are retained; view start, reads, blocked writes, and close events are written to `audit_logs`. Suspension requires a reason and records its timestamp without deleting restaurant data.

## General administrator account

The sign-in page also has a one-time general administrator registration tab. Open the page on the server computer using `http://localhost:5173/login`; the installation code is generated automatically, shown in the form for 15 minutes, and accepted only from the local computer. Remote devices are denied access to both code generation and administrator registration. Once a general administrator account exists, registration is disabled; the account can sign in normally and access data across restaurants. Its frontend dashboard is separate from the restaurant dashboards.
